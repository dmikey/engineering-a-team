# Cross-Agent Communication Protocol

**Version**: 1.0  
**Effective Date**: 2026-08-06  
**Review Cadence**: Quarterly (next review: November 2026)  
**Maintained by**: Council Moderator (Casey)

---

## Purpose

This document defines the standardized communication protocol for the AI agents
in this repository — Quinn (QA Engineer), Morgan (Project Manager), Alex (Product
Owner), and Casey (Council Moderator). It ensures that decisions, findings, and
updates are shared in a consistent, discoverable, and human-readable format so
that both agents and human contributors can participate in discussions and act
on outcomes.

---

## Guiding Principles

1. **English first** — All agent-to-agent messages are written in plain English
   so human contributors can read, comment, and redirect the conversation.
2. **Discussions over silent handoffs** — Decisions and updates are posted as
   GitHub Discussions (with an Issue fallback) rather than hidden in workflow
   logs or internal variables.
3. **Periodic advancement** — Agents revisit open discussions on a scheduled
   cadence, add new information, and surface items that need human input.
4. **Minimal noise** — Agents post only when there is something meaningful to
   say. Routine "no change" pings are suppressed unless an inactivity threshold
   is exceeded.
5. **Traceability** — Every message includes a workflow run link so stakeholders
   can audit the reasoning that produced it.

---

## Communication Channels

| Channel | When to use | GitHub mechanism |
|---------|-------------|-----------------|
| **GitHub Discussion** | Shared decisions, cross-agent reports, protocol updates | `createDiscussion` GraphQL mutation |
| **GitHub Issue** | Actionable findings, bugs, features, follow-ups | `POST /repos/{owner}/{repo}/issues` |
| **PR Comment** | Inline QA and code-review feedback tied to a diff | `POST /repos/{owner}/{repo}/pulls/{number}/reviews` |
| **Issue Comment** | Follow-up or advancement of an existing thread | `POST /repos/{owner}/{repo}/issues/{number}/comments` |

GitHub Discussions are the **primary** channel for cross-agent communication;
Issues and PR comments are secondary, task-specific channels.

---

## Message Format

Every cross-agent communication must include these four sections:

```markdown
## From: <Agent Name>
### Context
<What triggered this message: issue number, PR number, scheduled sweep, etc.>

### Update
<The substantive content: findings, decisions, recommendations, or questions.>

### Next Step
<What should happen next and who should act — another agent or a human.>

---
*🤖 <Agent Name> · <ISO date> · [Workflow run](<url>)*
```

### Required Fields

| Field | Description |
|-------|-------------|
| `From` | Full agent name and role (e.g., *Quinn (QA Engineer)*) |
| `Context` | Reference to the trigger — issue #N, PR #N, "scheduled sweep", etc. |
| `Update` | The substantive content; plain English, structured with headers and lists |
| `Next Step` | A clear, concrete next action with an optional owner |
| Footer | Auto-generated by the workflow; includes agent name, date, and run URL |

## Conversation Thread Lifecycle

```
Open Discussion
     │
     ├─► Agent posts initial finding / proposal
     │
     ├─► Human contributors may comment (any time)
     │
     ├─► Scheduled advancement check (weekly by default)
     │      ├─► If resolved: agent posts closure summary, marks resolved
     │      └─► If stalled (≥ 14 days no activity): agent posts a prompt
     │              asking whether human input is needed
     │
     └─► Discussion resolved or superseded by a council decision
```

### Lifecycle Labels

| Label | Meaning |
|-------|---------|
| `comms-open` | Active cross-agent discussion awaiting input or action |
| `comms-pending-human` | Stalled; a human decision or comment is needed |
| `comms-resolved` | Discussion concluded; no further action required |

## Agent Responsibilities

### Quinn (QA Engineer)
- Post PR review summaries to the linked PR.
- Escalate HIGH/CRITICAL findings as Issues tagged `bug` or `security`.
- Notify the council (via Discussion) when a risk pattern affects multiple PRs.

### Morgan (Project Manager)
- Post sprint summaries and backlog grooming results as Discussions.
- Comment on blocked Issues with a proposed unblocking plan.
- Advance any `comms-open` discussion that relates to delivery timelines.

### Alex (Product Owner)
- Post product health reports and feature proposals as Discussions.
- Respond to `comms-pending-human` discussions that are product-strategy related.
- Open feature issues referencing the relevant discussion thread.

### Casey (Council Moderator)
- Facilitate multi-agent discussion threads.
- Synthesise conflicting agent views into a numbered action list.
- Run the scheduled advancement check for all `comms-open` discussions.
- Update this document each quarter based on agent feedback captured in
  Discussions tagged `comms-protocol-review`.

---

## Quarterly Review Process

1. Casey opens a Discussion titled **"📋 Quarterly Protocol Review — Q\<N\> \<YEAR\>"**
   in the *General* category.
2. Each agent posts a short feedback section using the standard message format
   (`From`, `Context`, `Update`, `Next Step`).
3. Human contributors are invited to comment within 14 days.
4. Casey synthesises the feedback and opens a PR updating this document.
5. The PR is merged after at least one human review approval.

---

## Escalation Path

```
Agent finding → Discussion / Issue
     │
     ├─► Not resolved within 7 days → Morgan adds priority label
     │
     ├─► Not resolved within 14 days → labeled comms-pending-human
     │
     └─► Requires cross-agent alignment → council-review label
              → council-discussion.yml workflow triggered
```
